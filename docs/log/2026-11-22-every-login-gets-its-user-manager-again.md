`boot:logind` failed from v20261120.03 on: `systemctl --user` found no manager. Sessions have been of class `user-early-light` since 11-13, and logind starts no manager for one (`SESSION_CLASS_WANTS_SERVICE_MANAGER`, systemd v259.9). spin's linger had been the only thing that started `user@1000`, and e807038 (11-20, "spin does not linger") took it away. Root, the user spin logs in as, never had a manager on that path (inferred from the same code; not checked on a release). *Bisected* on the laptop, KVM, `boot:logind` against each release: v20261120.02 passes; v20261120.03, .04, v20261121.01 and v20261122.01 fail. e807038 is the only image commit between .02 and .03. v20261122.01 passes with `/var/lib/systemd/linger/spin` written back into the test's root. `lab tree --edit nolinger` did not reproduce it, because `boot:logind` boots its own raw copy of the base and never applies a tree's edits. *The fix.* `user-runtime-dir@`'s `20-manager.conf` wants `user@%i`. logind starts that unit for every session and waits for it alone, and the manager starts after it, so the login does not wait for the manager. *Measured* (bench, nested, spin's shape and login, 20 a side interleaved against v20261122.01, the drop-in and the class put into the overlay by experiment edits on branch exp/user-manager-462, 5ba7507): the drop-in first login +2.6 [−4.0, +8.7], restored login +0.8 [−1.5, +4.5] evicted and +1.0 [−1.1, +5.8] cached, cold login in the restore run +3.7 [−1.7, +10.5], all within noise. Accept to login +5.1 [+2.8, +6.5] and the second login +15.8 [+14.2, +16.6]: the manager runs while the second login does. Class `user-early`, which holds the login for its manager, cost the first login +36.2 [+32.0, +45.7], so it was rejected. *Checked:* `boot:logind` passes with the drop-in. With the console `su` login taken out of the check, the first SSH login's own `systemctl --user` still fails 3 of 3 with the drop-in, and passes 2 of 2 with class `user-early`. A command that needs the user bus at once in the first login can arrive before the manager. *Status:* in place. The manager's own cost is what would let a login wait for it (#467).
