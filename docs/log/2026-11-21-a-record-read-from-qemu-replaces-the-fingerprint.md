The fingerprint was a sha256 over a prediction of the machine (`Spec.Contract`, the shape, the BIOS file's size), passed to QEMU as `-name` and read back. A refusal could not say what differed. spin overwrote its probe's fingerprint with one computed from a Spec of placeholders. And the release's `fingerprint_sha256` hashed the CLI's default machine, not spin's, so v20261120.03's notes said checkpoints still resume when spin's shape had moved (`max_target`). *Measured* (laptop KVM, QEMU 11.2.0-rc0, v20261120.04, mapped-ram, the fingerprint taken out so that QEMU decides): QEMU refuses by itself fewer or more boot vCPUs, another vCPU ceiling, another virtio-mem size, a missing device, a smaller RAM or BIOS block and another machine type. It loads silently an extra device (a vsock the guest never finds), a larger BIOS block and more base RAM, because mapped-ram's `parse_ramblock` refuses only a smaller block, and a larger `max_target`, whose extra targets the guest used. A QMP dump of spin's shape: between a machine held and the same machine after a boot, a memory plug, the balloon polled, a vCPU and a disk added, only the balloon's statistics, virtio-mem's sizes, ICH9-LPC's `pm_io_base` and `gpe0_blk` and the RTC's date moved; between two machines, the MAC, the vsock's context id and vmgenid's GUID. *Result:* `QEMU.Target` reads the machine from the running QEMU (every device it was started with and every property but those, its options, its RAM blocks, the features its vCPU has on), and `CanResume` compares two records and returns a `*Refusal` naming every difference. `max_target` may grow; the CPU's features compare as one set, so a richer host is refused too. At spin's shape the record is 25.6 KB of JSON and 126 features, read in 8 round trips, 8.4 ms (boot:record). boot:record holds a machine to its own checkpoint and the silent cases to a refusal by name. boot:compat checkpoints the release before with this tree's `spin-machine save` and compares records; its local run on v20261120.04 resumed. *What it costs:* read inside `Resume`, the destination's record put its 8 round trips on the second goal number: restore-first's first login +4.3 ms [+0.2, +7.5] evicted and +8.2 [+6.2, +10.8] cached against v20261120.04 (bench, lab 44868324811). None of it could leave the clock: QEMU answers no monitor while it loads a state, and a read on a second monitor from QEMU's greeting stayed on it (laptop, +29 ms against +16 read in `Resume`), because QEMU's main loop is busy from its exec to the end of the load. The source's record is read while QEMU writes the state, where QEMU does answer, which brought `spin-machine save` from +7.0 and +10.6 ms (lab 44866054104) to within the noise (lab 44868324811). *Decided* (the maintainer, option C): the destination's record is a constant of a host, its QEMU binary, its CPU and the shape it resumes into, so `Resume` takes it from the caller (`here`), runs `CanResume` before it sends QEMU anything, and never asks QEMU. spin computes it once at runner start and holds each pool machine to it once (spin-stack/spin#1416). `spin-machine restore --target FILE` takes one as given, `spin-machine target` prints one, and the restore probes read each tree's record once before measuring, from a machine held for a checkpoint in the probe's shape. With it, against v20261120.04, whose restore reads its fingerprint record (name, version and CPU, five round trips) inside the restore (bench, spin's shape, 20 each): restore-first's first login +1.0 ms [-2.3, +4.1] evicted and -3.0 [-6.2, +0.0] cached, running +0.1 [-1.7, +1.3] and -1.4 [-2.9, -0.7] (lab 44871809382); prestart within the noise in every row, its restored login -2.5 [-4.3, +0.3] and restored into a QEMU started ahead -1.6 [-3.1, +2.1] (lab 44872699993). A checkpoint or a stored identity from before is refused, as a `vmm` difference, and boots from disk once. A newer QEMU that adds a property to a device is a refusal, which boot:compat reports at the bump. `Spec.CPUWithout` and `Unshared` are there for spin#1417's pools, not yet measured. *Status:* in place; spin follows (spin-stack/spin#1416).
