The image installs Ubuntu's openssh 1:10.2p1-2ubuntu3.8 rebuilt from its source package (`image/openssh`, versions.yaml `openssh-source`) with `userauth-delay-failures.patch`: `input_userauth_request` skips `ensure_minimum_time_since` for a request that authenticated, or for a public key query sshd answered with `PK_OK`, and keeps it for every other request but `none`. Ubuntu's package changes nothing on that path. It carries d43ba60 (CVE-2026-60001), whose keyboard-interactive and GSSAPI follow-ups delay only a failure, so the patch tests the method (`m == &method_pubkey`) and not `postponed` alone: those methods' first requests set `postponed` and keep their delay. The packages are `+spin1` and held, as systemd's. *Measured* (bench, nested, spin's shape and login, 30 a side interleaved, v20261122.01 against itself with this checkout's OpenSSH, `lab tree --openssh`): restored login 93.2 → 79.6, −13.6 [−14.9, −9.8] evicted and −13.6 [−16.2, −11.4] cached, `running` −0.3 [−1.9, +3.1] (lab 44983986606); the cold first login 467 → 457, −9.4 [−15.8, −2.6], sshd accepting −3.4 [−8.2, +0.6], accept to login −6.0 [−10.1, −4.8], the second login −10.9 [−12.3, −9.0] (lab 44983986575). The restore matches the `LD_PRELOAD` bound (−13.4). The cold login, which the bound read as within noise at −3.2 [−13.7, +2.7], moved too. *Checked* (`boot:sshd-delay`, laptop, 10 logins): the signed request of a login took 16.8 ms on the release's sshd and 1.9 ms on this image's; every refused key and unknown user still took 5.8-9.1 ms. The query's own turn shows no delay on either, because `PK_OK` goes out before it: the query's delay holds up the signed request. *Found on the way:* `debugfs cat | grep -q` on a binary fails under `pipefail` (debugfs takes SIGPIPE when grep stops at the match), so build.sh dumps sshd-auth to a file before it asks. *Status:* in place. The success half is upstream's intent and should be offered to OpenSSH (#457).
