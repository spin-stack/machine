*Lever 1:* every `vp_modern_*` queue accessor writes `queue_select` first, so setting up 13 queues wrote it 91 times. The same patch as 0011 (deleted with two others in a group arm, #345), here alone (branch `exp/592-l1-queue-select`), writes it 23 times. The MSI-X vector read-back after writing a queue's vector stays: virtio 1.2 §4.1.5.1.2 says a device refuses a vector by reading back NO_VECTOR and the driver must check, and `vp_find_vqs` falls back to shared vectors on it. *Lever 2:* each MSI-X message was written at activation and again by x86's `msi_set_affinity` before startup (`IRQCHIP_AFFINITY_PRE_STARTUP`, ff363f480e59), with the same vector and destination. A patch (branch `exp/592-l2-msix-once`) returns without the write when neither changed; a skip in `__pci_write_msi_msg` would have broken the restore of MSI state after resume. *Measured* (bench, nested, spin's shape and login, against v20261123.04, 3 a side for exits): lever 1 MMIO exits −68, lever 2 −56 (14 messages of 4 accesses, not the 19 inferred). The first login: lever 1 −2.8 [−6.6, +3.4] at 60 a side and +0.6 [−1.8, +2.3] at 120; lever 2 −0.1 [−3.1, +4.5] at 60. *The bound:* #590's, #591's and these patches in one kernel (branch `exp/batch2-bound`, 0017 refreshed to apply after 0016): every exit −838, MMIO −366, the host's handling −5.2 [−11.2, +1.2] ms (lab 45114428660); first login −7.4 [−12.1, −2.8] and sshd accepting −10.5 [−14.9, −4.1] at 60 a side (lab 45114405201); the restored login +0.0 [−5.4, +4.9] evicted (lab 45115341056). A bound is not a candidate; #627 asks whether the five are one change. *Lever 3:* spin's runner redials vminitd's RPC port every ≤2 ms until it listens (spin-stack/spin `internal/runner/qemu/guest_rpc.go`, `connectVsockRPC`), so spin's path pays refused-dial resets as the probe's dial did; how many is spin's to count (spin-stack/spin#1661). *Status:* levers 1 and 2 rejected.
