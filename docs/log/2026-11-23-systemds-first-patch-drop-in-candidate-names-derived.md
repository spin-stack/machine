#574's second experiment. PID 1 spends most of its loading in `unit_file_find_dirs()`, once for every unit name or alias, lookup directory (~12) and drop-in suffix (4), and each call worked out the unit's candidate names again: the name, its template, its "-" prefixes. Upstream's #42858 (Eric Curtin, merged 2026-07-25, in v262) works them out once per name, `manager_enumerate()` 45.35 → 38.81 ms in its author's container (50 runs, ~270 units). Yocto backported it to 259.5, with an unrelated `CONF_FILES_WARN` change beside it, so the backport here is upstream's commit with one removed line's context moved to 259's `set_get()`. *Measured* (bench, spin's shape and login, v20261123.01, each arm systemd rebuilt on the runner, against a control rebuilt with a comment and no code changed, so both install their packages the same way): first login −6.5 [−9.9, −1.3] at 100 a side, sshd accepting −6.1 [−10.0, −1.1] (lab 45090299768). PID 1's CPU from its exec to the login's sshd-session, 55.1-57.8 ms on the control and 48.1-53.4 with the patch, 5 ledgers each (lab 45090326943). Restored, 20 a side: −0.9 [−4.3, +3.0] evicted, −1.4 [−5.0, +2.1] cached, within noise (lab 45091690423). *Changed:* image/systemd carries its first patch, applied without fuzz after Ubuntu's, as image/openssh does; the Dockerfile fails when it does not apply or its function is not in the source; the release ships it under `usr/share/spin-stack/systemd/` and names it in SOURCES, NOTICE and the SBOM's pedigree. A bump to 262 drops it. *In the same run:* #574's third experiment, no unit made for a `RequiresMountsFor=` prefix with no unit file, read −1.0 [−4.3, +3.9], and PID 1's CPU did not move: rejected, in "Measured and rejected", with the patch and an upstream draft kept in #580. *Status:* in place.
