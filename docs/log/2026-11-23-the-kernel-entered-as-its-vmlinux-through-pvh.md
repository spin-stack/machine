*Why:* a bzImage's decompressor spent ~21 ms (bench) on a copy, LZ4 and parse_elf before the kernel's clock, and it was the only thing that randomized the kernel; PVH skipped it and left the kernel at its linked address (11-19). *The bound first*, a vmlinux through PVH with no KASLR at all, against the same build as a bzImage: first login −18.9 [−22.8, −12.4], restored −3.6 [−5.1, −2.1] evicted, at 40 a side. *Two paths with KASLR kept:* QEMU applying the relocations (Holmes et al., EuroSys '22; Firecracker's design) or the kernel applying its own (Hou Wenlong's RFC, 2026-01-26). The kernel's own was chosen: no relocation format for QEMU to parse, nothing on QEMU's command line, the decompressor's entropy code (#645, issuecomment-7106937337). *Carried:* the RFC as kernel 0014-0018, made checkpatch --strict clean with each change noted in its header; 0019, which sets `KASLR_FLAG` once the kernel moved (without it `RANDOMIZE_MEMORY` left the regions where they were: the lowest vmalloc address ffffc90000000000 and the direct map ffff888000000000 at every one of 10 boots, lab 45225297602; with it, 10 distinct bases of each, lab 45221660056); 0020, because the RFC reads RDRAND from CPUID leaf 1's EDX and the TSC from its ECX, the wrong way round, so its virtual base was drawn from the i8254 and a hash of `boot_params` alone, on a guest that has `rdrand` and `tsc` and no `ds_cpl` (lab 45225297602); QEMU 0008, a random physical base from `XEN_ELFNOTE_PHYS32_RELOC`. The relocation table needs 0xc7000 bytes of the 1 MiB reserved: a 512 KiB reserve failed the link naming that size (parts run 45222305257). The machine boots a release's vmlinux when it carries both Xen notes and its bzImage otherwise, so a release from v20261119.02 to v20261123.06 boots as it did. *Measured* (bench, spin's shape and login, against v20261123.06, 60 a side, the kernel without 0020): first login 368 → 352, −16.8 [−20.9, −13.0], sshd accepting −16.7 [−20.2, −12.7], QEMU's RSS −13.8 MiB (lab 45219785493); restored −4.4 [−17.5, −2.0] evicted, −4.3 [−14.0, +10.2] cached, the state −31.9 MiB, the save −14.6 (lab 45219801969). *Status:* kept. What the bzImage, `KERNEL_LZ4` and QEMU 0007 still serve is #660.
