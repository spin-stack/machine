A compat run on #443's branch took ~10 minutes (run 44974499826): `boot:checkpoint-pause` 311 s, building QEMU and the kernel 239 s (QEMU's cache missed), the releases' checkpoints resumed 109 s, the rest ~40 s. It ran only on main after a merge, so #435, which sent `x-defer-disk-flush` to every QEMU, was found after it merged. *Moved:* `boot:checkpoint-pause` is a bound, not compatibility. It runs in release.yml's `pause` job on a bench host once a release is published, and the qemu entry's bump note names it. Its run there (lab 44978556859, v20261122.01) held idle 23.0, writing 16.8 and beside a busy disk 17.9 ms p50. *Built:* compat runs on every pull request beside CI. A `changed` job decides whether the change reaches the machine, QEMU or the kernel. A part it does not reach is not built: QEMU is main's published one (`fetch qemu`, 10 s) and the kernel the release's. A `compat` job at the end reports on every change, so a ruleset can require it as it requires `parts`. `changed` now compares from the merge base, so a dispatched branch is not charged with what main gained after it forked. *Built:* `go test` holds the machine package to every supported release's `query-qmp-schema` (`internal/qmpdef/testdata/released`, recorded from each tarball's `qemu-system-x86_64` by `spin-machine-dev releases schema`, which report.yml runs on each release). `CheckSupported` holds what the package sends unconditionally to every release. A value or member only newer QEMUs have is `qmpdef.Probed` or tagged `qmpdef:"probed"`. `TestTheMachineDrivesEverySupportedQEMU` drives `Checkpoint` and `DiskUsage` against a fake QEMU that refuses what each release's schema refuses, in QEMU's words. *Proved:* with #439's fix reverted, that test failed for v20261119.02 to v20261121.01 with `Parameter 'capability' does not accept value 'x-defer-disk-flush'`, compat 44964906186's error, in ~2 s. v20261122.01 and the pinned QEMU have the capability and passed. With DiskUsage's fallback removed it failed on all seven releases, since only the pinned QEMU has `x-flat`. *Measured:* compat dispatched on a change that reaches neither part took 4m02s wall, its KVM job 3m03s, of which resuming the seven releases' checkpoints was 103 s and fetching QEMU 10 s (44979352669). On this branch, which touches `internal/build` and so builds both parts from a warm cache, it took 3m57s (44978948650). *Status:* in place.
