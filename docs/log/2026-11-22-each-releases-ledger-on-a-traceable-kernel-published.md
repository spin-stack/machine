The ledger (#533) needs tracefs, which the release kernel's lockdown at confidentiality takes away, so it ran only on demand, on a kernel from a scratch branch kept as a run artifact that expires (`run:45061289985`). *Decided:* option 1 of #536 at release cadence. release.yml's `traceable` job builds the release's kernel source and config with `KERNEL_LOCKDOWN=none`. `release traceable-kernel` holds its config to the release kernel's, lockdown swapped and every other option equal. The job signs the bzImage and publishes it on the release as `…lab-only-traceable.bzImage`: in no tarball, in no SOURCES, in nothing spin boots. Options 2 (a `lockdown=` parameter) and 3 (on demand only) were not taken: 2 trades spin's compile-time guarantee for a command-line one, and 3 left no ledger per release. `lab tree --kernel traceable:TAG` checks the signature, `releases measure` takes one ledger of each release on that kernel beside its boot chart, and the record keeps it as `docs/releases/TAG-ledger.txt`. *Measured:* built as the `traceable` job builds it, the kernel passed the config check against the release kernel of the same job (parts run 45071066129). The ledger on it, with v20261122.06 and drawRelease's tree, gave 3 of 3 ledgers: 0 breaks, 0 events dropped, residue 0.6 ms p50 and first login 427 ms p50, in spin's shape (lab 45073394754). That release's record read 414.4 cold in the same shape, so the +13 is within the ledger's own ~16 ms. *Cost:* one cold kernel compile per release, 10 min after the release kernel's, in a job of its own so that pause and wake do not wait for it. report waits for it. A change that breaks the traceable build is first seen at release time (#558). *Status:* in place. The first release built with it is the first with a ledger.
