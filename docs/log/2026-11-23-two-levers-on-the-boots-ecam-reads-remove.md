*Why:* since 0004 every configuration read is an MMIO exit, and #591 counted the reads by caller. *(a)* `pci_bus_add_device()` saves every device's state at its add (upstream a2f1e22390ac, v6.19, for error recovery), 16 reads for each of 8 functions. A patch (branch `exp/591a-no-save-state`) keeps the save only where something can restore it without the driver's own save: AER (and DPC and EDR, which need it), EEH, s390, Xen's pcifront, and a root-bus device whose host bridge sets `reset_root_port`. CONFIG_PCIEAER alone was not a safe gate, because the same commit took out `pci_restore_state()`'s refusal of a state never saved, and those mechanisms call drivers' error handlers without AER. *(b)* `vp_modern_probe()` walked the vendor capabilities once for each of four types; a patch (branch `exp/591b-virtio-caps-once`) walks them once and keeps the first usable one of each type, as before. *Measured* (bench, nested, spin's shape and login, against v20261123.04): (a) MMIO exits −128 exactly, the host's handling −3.3 [−6.2, −2.1] ms; (b) −114 exactly, both at 3 a side and both the counts the source gave. The first login at 60 a side: (a) −4.3 [−6.8, +0.5], within noise; (b) −5.8 [−8.2, −0.6], outside it, but 114 exits at ~15 µs each (10 in the L1 and ~4.7 for the L0's trips) are ~1.7 ms, a third of that. A run of 120 a side, made because both arms straddled the noise, read (a) −1.3 [−3.5, +1.3] and (b) +0.9 [−1.8, +2.7]. The larger run decides, and it was chosen after the first was read, which this entry says. *Status:* both rejected. With #590 and #592's patches, as a bound, −7.4 [−12.1, −2.8] (#627). Lever 3, BAR sizing from the firmware, was not tried: it needs a new reason over the rejected configuration-space snapshot (11-13).
