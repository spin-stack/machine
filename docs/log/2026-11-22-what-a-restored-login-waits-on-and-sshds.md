With the disk gone from the evicted restore, the login after `running` is restore-first's largest phase (~35 ms). A connection that timed each write and read of the login (laptop, v20261122.01, one restore at a time) split a 32 ms restored login into 4.6 ms to the server's banner, ~5 ms of key exchange, 14.5 ms from the signed `userauth` request to `USERAUTH_SUCCESS`, and ~4.7 ms for the channel, `exec` and exit. sshd at `LogLevel DEBUG3` said where the 14.5 ms went: "elapsed 0.903ms, delaying 6.180ms" after the key query and "elapsed 1.468ms, delaying 5.615ms" after the signed request. Both are `ensure_minimum_time_since` in OpenSSH 10.2's `auth2.c`, which waits until 5 ms plus 0-4.2 ms have passed since a userauth request arrived. It runs while `authctxt->authenticated` is 0, and `userauth_finish` sets that flag only after it, so the request that succeeds sleeps too. The query sleeps after sshd has already answered `PK_OK`, before it reads the signed request. spin's users meet the query from both clients: `golang.org/x/crypto/ssh` always asks first, and OpenSSH's `ssh` does for a key whose public half it holds. *Bound* (an `LD_PRELOAD` shim in ssh.service whose `nanosleep` returns at once, `--edit nosleep` on branch `exp-nosleep`, not for merge; bench, nested, spin's shape and login, #447's spin-machine on v20261122.01, 30 each, interleaved): restored login −13.4 [−15.2, −10.5] evicted and −13.5 [−15.6, −12.4] cached, `running` +0.7 [−0.8, +1.5], the cold login before the save −3.2 [−13.7, +2.7], within noise. The cold login hides the sleep behind the boot work its vCPU still has. A laptop check that the shim took: sshd and `sshd-session` mapped it, and the signed request's turn fell from ~14 to 2.9 ms. The shim first went in through the edit's `Files`, which the manifest keeps as JSON, and arrived 136 bytes longer and was ignored; it goes in by `Setup` in base64. *Status:* open (#457). The candidate is a patch that skips the sleep for a request answered with `PK_OK` or that succeeds, which tells the client nothing it does not know, and keeps it for failures. It needs openssh rebuilt from Ubuntu's source, as image/systemd does for systemd.
