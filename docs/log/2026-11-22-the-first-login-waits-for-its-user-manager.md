Since #462 a login's manager started beside it, and the first login's own `systemctl --user` could arrive before it. On spin's login (root, bench, v20261122.03) it failed 10 of 10 (lab 45032247920, `ssh-first` with the first login's command `systemctl --user list-units`, archive tag archive/exp-user-manager-467). *Where the manager's time goes:* a diagnostic read root's manager's timestamps after the logins (`systemctl show` of `user@0` and the manager's own Generators/UnitsLoad timestamps). With class `user-early` the manager took ~48 ms from `user@0` starting to ready: ~11 PAM and exec, ~2.6 the manager's start, ~9 the XDG autostart and environment.d generators, ~2 unit load, ~8 building the first transaction (its lazy unit loads, a debug log showed), and ~15 sockets.target, which waits for dbus.socket's and ssh-agent.socket's `ExecStartPost=systemctl --user set-environment`. The user units are default.target, basic.target, sockets.target (dbus.socket, ssh-agent.socket, systemd-ask-password.socket), timers.target and paths.target with nothing in them, and app.slice. *Cuts* (bench, nested, spin's shape and login, 20 a side, against class `user-early`, lab 45030778365): the sockets' environment from `/etc/environment.d` and their ExecStartPost taken away −17.1 [−27.0, −10.7]; the XDG generator masked −4.8 [−11.2, +1.3]; both generators, a bound, −8.4 [−15.8, −1.0]; the PAM stack down to `pam_permit` and `pam_systemd`, a bound, −3.5 [−11.4, +2.5]. With the environment cut and the XDG mask, `user-early` still cost +29.8 [+17.2, +42.2] (lab 45031248191): what is left is systemd --user's own start. *Root lingering* moves that start into the boot, where the first login finds it done or nearly. Decided at 40 a side (lab 45031644179): `user-early`, the environment cut and root lingering, first login +4.7 [−0.2, +12.2], within noise; sshd accepting +5.6 [+1.1, +10.1]; the second login −16.7 [−17.7, −16.3]. Without the environment cut, +19.6 [+15.9, +25.6]. Restored login −10.8 [−15.9, −6.6] evicted and −12.3 [−15.1, −5.5] cached, 20 a side (lab 45031644114). The likely reason is that root's manager no longer stops 10 s after the cold login's session ends (`UserStopDelaySec`) and starts again beside the restored login (inferred, not measured). *Left out:* the XDG mask, which moved neither goal number. *The lane's login as spin* waits for spin's own manager: first login +29.7 [+22.8, +42.1], and shadowing Ubuntu's `user@` barrier on `systemd-user-sessions` changed nothing (+30.6, lab 45031687433). The lane is no goal number, and the no-systemd floor's Δ in the next release's record is read against it. *Changed:* class `user-early`, root's linger file, `environment.d/10-user-sockets.conf` and the two sockets' `10-env.conf`; `20-manager.conf` deleted, since logind starts the manager of every session of class `user-early` itself. `boot:logind` runs its SSH logins before the console `su`, so the first SSH login's `systemctl --user` is the first login's. `lab`'s lane edit carries the same. *Checked:* the first login's `systemctl --user` passed 10 of 10 on spin's login and on the lane's with these edits, the manager-wants drop-in removed (labs 45032247920, 45032247623). *Status:* in place.
