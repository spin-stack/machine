*Why:* a reader running the machine by hand, spin-stack/shirudo-demo and the "machine without spin" post, had no network in the guest: a NIC was a TAP only a caller like spin's runner makes, and the demo answered two URLs with a curl shim (#751). *Done:* a NIC is a TAP or passt (`machine.NIC.Passt`), and validate refuses both and neither. Start runs passt beside QEMU on a socket pair, as it runs swtpm, and QEMU reaches it through a `stream` netdev on the descriptor, with no vhost; passt ends with QEMU. QEMU stays `--disable-slirp --disable-passt`. The release ships `bin/passt`, 2026_10_02.cba3570 built static-pie in the QEMU Dockerfile's passt stage from versions.yaml's pin, refused unless static and hardened, and `verify qemu` asks it for `--fd`. passt's addresses are fixed, so the guest's side is a constant on the kernel command line: a `tmpfiles.extra` credential writes the `.network` and `/etc/resolv.conf`, and a `udev.rules.*` credential has systemd start systemd-networkd when `eth0` appears, because the image enables neither networkd nor its generator and has no systemd-debug-generator to read `systemd.wants=` (tried first: neither unit started). The image is not changed. `spin-machine boot --net` gives a machine one. *Seen:* `task boot:net` (laptop KVM, Ubuntu 26.04 host with unprivileged user namespaces restricted by AppArmor, no root): eth0 at `10.0.2.15/24`, the default route through `10.0.2.2`, github.com resolved and `curl -sSI https://github.com` answered `HTTP/2 200`, 3.4 s after the kernel started; a machine without a NIC has `lo sit0`. The record is the same for a NIC on passt and a TAP: ReadTarget holds each on a hub port. *Status:* `boot --net` is off by default, and spin's machines, whose NICs are TAPs, are unchanged.
