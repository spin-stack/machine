*Why:* a guest could not build shirudo's initrd itself: the image's systemd was built with Debian's `stage1` profile, which turns TPM2 off, so it had no `systemd-pcrextend` and no `systemd-pcrphase-initrd.service`, and `shirudo-gen-initrd --check` refused the initrd dracut made (#767). *Measured* on the bench, spin's shape, cold first login against main's systemd built in the same run, from the throwaway branch `lab/767-tpm2-bench`. systemd builds `systemd-pcrextend`, `systemd-tpm2-setup` and the tpm2 generator only with OpenSSL and the boot loader as well, and links OpenSSL into libsystemd-shared. One build with all three: +20.0 [+15.5, +26.8], 30 a side (lab 45835078883), and with `--tpm` +17.1 [+8.9, +25.2] (lab 45835128161). OpenSSL alone +9.7 [+1.6, +14.6], TPM2 alone −1.0 [−7.2, +7.6] (lab 45837372412): libcrypto loaded by PID 1, the executor of every unit and every daemon is the cost. So a second build of the same source with TPM2, OpenSSL and the boot loader (`image/systemd/tpm2.mk`), of which the package takes only what TPM2 adds. That build's tpm2 generator, the one piece of it a boot ran: with it +10.2 [+6.4, +13.1] and QEMU RSS +6.0 MiB, without it +6.4 [+0.9, +10.3] and +0.1 MiB (lab 45839499964); with `--tpm` +6.3 [−0.6, +14.7] and +3.3 [−3.4, +11.3] (lab 45839536973).
