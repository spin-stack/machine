*Why:* #565's `x-consistent-cache=off` changed CPUID leaf 2, and the record did not move: `machine.CPU` read feature bits only, so a checkpoint taken on one side of the change resumed on the other without a refusal. *Read* (QEMU 11.2.0-rc0's `target/i386/cpu.c`, `host-cpu.c`, `kvm/kvm-cpu.c`, 2026-11-22): the vCPU's properties that shape CPUID without being a feature bit, and of those, the ones `-cpu` sets or the host model takes from the host. #565's claim that a guest reads the same caches from either leaf does not hold under `host`. `legacy-cache` is on there, so with the switch off leaf 2 describes `legacy_intel_cpuid2_cache_info` (L2 2 MiB 8-way) while leaf 4 describes `legacy_intel_cache_info` (L2 4 MiB 16-way). glibc reads a 2 MiB L2 since v20261123.01 (#586). *Changed:* `CPU.Properties` holds `cpuidProperties`, read off the vCPU in the qom-list-get `CPU` already made: `x-consistent-cache`, `l3-cache`, `legacy-cache`, `host-cache-info`, `family`, `model`, `stepping`, `model-id`, `level`, `xlevel`, `phys-bits`, `guest-phys-bits` and `pmu`. `CanResume` refuses each difference as `cpu <name>`, and refuses a property only one side has. `TestTheRecordHoldsWhatTheCPUIsGiven` fails a `-cpu` option that is neither a feature, a feature filter (`migratable`, `enforce`) nor held. *Compatibility:* a record written before this change holds no property, and is refused by each, `cpu x-consistent-cache: checkpoint none, here false` among them. The record names no release, and v20261122.07 (switch on) and v20261123.01 (off) run the same QEMU, 11.2.0-rc0, so nothing in an old record says which side of the switch it was taken on. Reading it as either value would let the other side's checkpoints through. Every checkpoint saved by a released spin-machine boots cold once. `boot:compat` saves each release's checkpoint with this tree's spin-machine, so it reads each release's own switch. With this change alone, v20261123.02 and v20261123.01 resumed and v20261122.07 was the first it refused, `cpu x-consistent-cache: checkpoint true, here false` (CI run 45099128633). The entry below rides in the same record change, and moves the first refused release to the newest. *Opened:* #586 (leaves 2 and 4 disagree under host), #587 (`Unshared` ignores the properties), #588 (leaf 0xA is the host's PMU and nothing holds it). *Status:* in place.
