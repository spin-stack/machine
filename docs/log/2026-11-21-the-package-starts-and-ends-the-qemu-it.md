Every caller assembled one QEMU's life itself: exec it, wait for the monitor's socket, dial, `qmp.New`, `Attach`, keep its output, kill and reap. In this tree there were ~7 such wrappers and ~8 dial loops, with poll intervals of 1, 5 and 20 ms, socket waits from 5 s to unbounded and handshake timeouts from 5 s to 2 min, and spin's runner had its own. `machine.Start(ctx, Spec, StartOptions)` now returns a `*machine.Process`: the `*machine.QEMU` its own monitor drives, with the process under it. Start opens and hands QEMU every descriptor the Spec implies (each monitor's socket, bound by Start, `/dev/kvm`, `/dev/vhost-vsock`, `/dev/vhost-net` per NIC, a `file:` console), so QEMU opens no path. The caller keeps its TAPs and disks, and shapes the process (uid, chroot, namespaces, cgroup) through `StartOptions.Cmd`, which runs after the opens. Readiness is Start's own monitor, bound and connected before QEMU exists and answered by QEMU's main loop once the machine is made. Nothing is polled. `Exit` holds the wait status, the last `SHUTDOWN`, the console's panic line when Start reads the console, and stderr's last 4 KiB. `Stop` presses the power button of a running guest, then quits, then sends SIGKILL, each step bounded. A monitor silent for 1 s (a QEMU loading a state) is killed. `machine.Dial` replaces the dial loops for a second monitor. `spin-machine boot` starts QEMU through Start and waits beside it, with Pdeathsig, instead of exec'ing it with a `_bind` helper. *Observed on real QEMU* (laptop, KVM and TCG, v20261121.01's QEMU): a held machine stopped is quit, `exit status 0` with SHUTDOWN host-qmp-quit. Killed, it reads `signal: killed` with no SHUTDOWN. A refused device fails the start at once with QEMU's line (`Property 'virtio-balloon-pci.no-such-property' not found`). `poweroff -f`, `Shutdown` under systemd and a panic end as guest-shutdown, guest-shutdown and guest-reset, exit status 0 (boot:record). *Measured* on the bench, spin's shape and login, v20261121.01 with its own spin-machine against the same tree with this branch's: ssh-first's first login +0.5 [−5.2, +8.3] at 20 boots (lab 44912292706) and −2.9 [−7.0, +5.0] at 40 (lab 44914952228), sshd accepting −3.5 [−6.8, +3.1], within noise. restore-first at 20 read the cached login +3.6 [+1.5, +4.5] (lab 44912896763), and at 40 +0.4 [−1.7, +3.1] evicted and +0.7 [−2.1, +3.1] cached, running +2.2 [−0.1, +5.2] and +0.4 [−1.1, +2.9], within noise (lab 44914490616). The cached cold login inside that run read +4.9 [+1.8, +9.5], where ssh-first's 40 cold logins read −2.9, so it is read as the probe's noise and left for the next release to confirm or not. *Why no gain:* the dial polls were never on the clock. A client polling the socket found it long before QEMU could answer, because QEMU makes the socket early in its start and answers only once the machine is made (the `transport` entry above: spin-machine's first command waits 17 ms on QEMU). *Status:* in place. spin follows, in place of its runner's own start, handover and shutdown.
