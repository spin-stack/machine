spin already makes, pins and hands over the workspace's host key. vminitd makes an Ed25519 key, the launch claim carries its public half, the control plane connects with it fixed, and before it execs systemd vminitd writes it to `/run/spin/ssh/ssh_host_ed25519_key` with a drop-in naming it sshd's only `HostKey`. The image's `spin-machine-sshd-keygen` still ran on ssh.service's path, 6.2 ms of CPU (ledger, v20261122.07), for a key nothing loads. So the brief's plan (a systemd credential through fw_cfg, a Spec field and a kernel option to read it, spin making the key on the host) was not needed. *Changed:* the unit carries `ConditionPathExists=!/run/spin/ssh/ssh_host_ed25519_key`, read back by build.sh. `ssh.service.wants/spin-machine-sshd-keygen.service`, a symlink checked in since `2df3dbf` that #515 could not trace, wanted the unit a second time and is gone. The sysinit want stays for the lane. The lab's `--edit spin-handoff` stands in for vminitd's handoff: a fresh key per boot, made on the host, and a shell as PID 1 that places it and execs systemd. *Measured:* on the bench, spin's shape and login, against v20261122.07, both arms with the handoff. At 60 a side the first login read −6.8 [−11.8, +0.2] (lab 45085877480), under the ~6 ms ceiling's noise, so the run that decided it took 120 a side: first login −6.9 [−9.6, −2.4], sshd accepting −6.8 [−10.4, −1.8]. In the same run, the ssh.service want taken away read −1.6 [−3.7, +4.3], which rule 5 deletes (lab 45086250796). Restored, 20 a side: restored login −0.6 [−3.1, +4.7], cold −9.0 [−16.3, +2.8], within noise (lab 45085877238). `boot:logind` and `boot:workspace` passed on the arm (labs 45085886063, 45086216266). *Opened:* #575, because `login=spin` does not hand over a key, so its probes still pay the keygen. spin-stack/spin#1650 records `HostKeyPath` as the image's contract. *Status:* in place. The arms' edits (`keygen`, `keygen-unwanted`) are removed.
